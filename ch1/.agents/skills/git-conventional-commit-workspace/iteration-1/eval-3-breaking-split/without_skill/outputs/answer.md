建議依三個獨立目的拆成三個 commit，方便審查及個別回復。

1. 提高最低 Node 支援版本：

   ```text
   chore(runtime)!: 將最低 Node.js 支援版本提高至 22

   BREAKING CHANGE: 執行此套件需要 Node.js 22 或更新版本，不再支援 Node.js 18 至 21。
   ```

   這會影響仍使用舊版 Node 的使用者，應標示為破壞性變更。`!` 與 footer 擇一即可；這裡同時使用，讓影響更明確。`chore` 的實際發布處理取決於專案工具設定。

2. 修正 README 錯字：

   ```text
   docs: 修正 README 錯字
   ```

   單純文件錯字通常不影響套件版本。

3. 回復快取變更：

   ```text
   revert: 回復 abc1234 的快取變更

   回復提交：abc1234
   ```

   尚未看到該提交的 diff，無法判定回復對外部行為及相容性的影響，也不能直接認定它屬於修補或破壞性變更。

若套件採用 SemVer，穩定版中的破壞性變更通常需要提升 major；0.x 階段及實際發布規則需另看專案政策。沒有目前版號及 release 設定，無法給出確定的下一版號或保證自動發布結果。
