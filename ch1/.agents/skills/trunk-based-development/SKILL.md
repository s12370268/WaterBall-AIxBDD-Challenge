# Trunk Based Development

協助團隊把小批次變更頻繁整合到共同主幹，保持可建置、可測試、可按需發布。預設以繁體中文回答，保留專案既有工具、分支名稱與使用者指定語言。

## 先建立正確判準

- 主幹是共同整合點；名稱可以是 main、master 或 trunk。不要為名稱改動專案。
- 短命分支與 PR 可以符合主幹開發。重點是實際回到共同主幹的頻率，不是禁止分支。
- 以每位開發者至少每日整合為方向，理想是數小時內完成小變更；官方短命分支文獻的外緣是約一至兩天。review 與排隊時間也算生命週期。每天把 main 拉入兩週功能分支不算每天整合。
- 區分程式整合、部署與對使用者開放功能。維持可發布，不代表每次 merge 都必須正式發布。
- CI 是團隊頻繁整合並透過自動建置與測試驗證的實踐；只有在長命分支執行 pipeline 並不足夠。

## 工作流程

先閱讀 [主題索引](references/topic-map.md) 核對關鍵字、方法、規則與例外；再依下列步驟處理任務。

1. 辨識要求：解釋、現況診斷、遷移計畫、切分變更、流程設計，或實際修改 repo。有足夠資訊就完成；僅針對影響決策的缺口提問，並標示其餘假設。
2. 需要 repo 證據時，先讀 AGENTS.md、CONTRIBUTING、CI 設定、測試與發布腳本；再使用相關唯讀 Git 檢查，例如 `git status --short --branch`、`git branch -a`、`git log --all --oneline --decorate -30`。依可取得資料識別主幹、保護規則、branch 年齡、review 等待及建置時間。沒有 remote/CI 資訊就說未知，不能從最後 commit 時間推定 branch 建立時間，也不能從本地設定推定遠端保護規則。
3. 根據並行寫入者（含 AI agents）、commit 流量、審查要求和測試可信度選整合模式。小團隊可直接整合但仍需驗證；有保護規則或多人並行時採短命 PR，流量高時考慮驗證整合結果的 merge queue。不要用固定人數門檻代替判斷，也不要以實施 TBD 為由繞過必要審查。
4. 把需求切成獨立可測、可整合的小步。每一步列出變更、相容性、驗證及整合完成條件。整個功能要做數週，不代表 branch 要存活數週。依需要讀 [實作模式](references/patterns.md)。
5. 設計快速回饋：整合前執行適當建置與測試；PR 驗證與最新主幹的整合結果；整合後持續驗證共同主幹。建置變紅時優先恢復，短時間無法修好就以一般 revert 還原問題變更並保留歷史。不要靠忽略失敗測試維持表面綠燈。
6. 按交付限制選從主幹發布，或必要時從已知良好 commit/tag 晚切 release branch。依 [發布與遷移](references/delivery.md) 處理 backport、支援版本與逐步轉換。保留一條主要開發線，release branch 只承接受控修補。
7. 提供相應產物並檢查：有沒有留下長命功能線、review 瓶頸、失效 flags、破壞相容性的中間步驟，或把部署頻率誤當整合頻率？區分實際驗證、提議與待確認項目。

## 按任務交付

- **解釋或比較**：直接說明差異與具體例子。需要理論、數字或來源差異時讀 [研究與來源](references/research.md)。
- **現況診斷**：列出「觀察／證據 → 與 TBD 的落差 → 優先行動」，指出缺少資料。不能只憑使用 main 或有 CI 宣稱已採用。
- **導入或遷移**：提供階段、負責角色、可驗收退出條件，以及整合頻率、branch 生命週期（含等待）、review 等待、CI 回饋時間與主幹恢復時間的量測方式。數值目標要區分文獻、團隊約定與示範建議。
- **大型功能或重構**：提供有順序的小步表，包含 flag/abstraction、向後相容、測試、啟用與清理。資料庫變更需處理舊新版程式並存。
- **修改 repo**：在既有工具中做必要改動，執行適當驗證並回報結果。純諮詢任務只提供方案；不要順便變更程式或遠端設定。

## 操作邊界

依使用者實際授權執行 Git 寫入、push、merge、部署與遠端設定；skill 本身不構成授權。保留未提交工作。不要為轉換流程強制推送、重寫共同歷史、批次刪分支或直接移除保護規則。若目前目錄不是 Git repo，依使用者提供情境完成建議，不自行初始化。

範例：使用者說「付款重構需三週，怎麼每日合併？」先建立舊實作的介面與回歸測試，再以數個小 PR 加入預設關閉的新實作、驗證切換與回退，分批啟用，最後刪除過渡程式。不要回覆「開三週 feature branch，每天 rebase」。
